## Purpose

The 30-Day Pilot Plan moves one selected workflow from discovery to limited deployment without pretending the organization has already solved governance, data, or adoption.

The pilot is designed to answer one question:

> Can this workflow be improved by AI in a way that is reliable, measurable, human-governed, and worth scaling?

## Pilot Guardrails

The pilot should be:

- Narrow
- Measurable
- Owner-approved
- Human-reviewed
- Evaluation-driven
- Limited in production exposure
- Designed to generate a next-build recommendation

The pilot should not become a broad transformation program.

## Week 1: Workflow Discovery

### Objectives

- Identify 5-10 candidate internal workflows
- Score each workflow using PEOM intake
- Select one build-first workflow
- Confirm named owner and executive sponsor
- Define baseline metric

### Activities

- Stakeholder interviews
- Workflow intake scoring
- Current-state process map
- Data and tool access review
- Risk classification
- Success metric definition

### Outputs

- Ranked workflow candidate list
- Selected pilot workflow
- Named workflow owner
- Baseline metric
- Initial risk readout

## Week 2: Prompt and Context Prototype

### Objectives

- Decompose the selected workflow
- Define what AI should automate, augment, or avoid
- Build first prompt and context design
- Identify tool/API needs
- Run initial evaluation checks

### Activities

- Task decomposition
- Prompt design
- Context mapping
- Output format definition
- Human review point design
- Initial test case creation

### Outputs

- Prototype prompt
- Context design
- Human review model
- Initial test cases
- First-pass evaluation results

## Week 3: Evaluation and Feedback

### Objectives

- Complete evaluation matrix
- Run edge case and regression tests
- Collect workflow owner feedback
- Revise prompt and context design
- Define acceptance criteria

### Activities

- Accuracy testing
- Consistency testing
- Grounding checks
- Hallucination review
- Edge case testing
- Workflow owner review
- Regression baseline creation

### Outputs

- Evaluation matrix
- Failure log
- Revised prompt version
- Accepted test cases
- Deployment recommendation

## Week 4: Limited Pilot and Executive Readout

### Objectives

- Deploy the workflow in a limited setting
- Track business impact
- Monitor human review outcomes
- Capture escalation signals
- Produce executive readout

### Activities

- Limited pilot launch
- Weekly owner check-in
- Acceptance and edit tracking
- Escalation review
- Business impact measurement
- Next-build recommendation

### Outputs

- Pilot results
- Governance model
- Business impact summary
- Scale / pause / redesign recommendation
- 90-day next-build roadmap

## Success Metrics

Select metrics before launch.

Examples:

| Metric | What It Proves |
|---|---|
| Time saved per workflow instance | Operational leverage |
| First-pass acceptance rate | Output usefulness |
| Edit rate | Quality and trust |
| Escalation rate | Boundary performance |
| Error reduction | Reliability |
| User adoption | Workflow fit |
| Turnaround time reduction | Speed improvement |
| Owner confidence | Deployment readiness |

## Pilot Decision

| Outcome | Decision |
|---|---|
| Strong impact, low risk, high owner acceptance | Scale |
| Strong impact, manageable failures | Fix and extend pilot |
| Weak impact, good quality | Reassess workflow priority |
| High risk, low acceptance | Pause |
| No owner, no metric, no review path | Do not deploy |

## What This Pilot Does Not Include

The 30-day pilot does not include:

- Enterprise-wide rollout
- Full platform implementation
- Long-term managed service
- Unrestricted production deployment
- Automation of high-risk decisions without human review
- Guaranteed business outcomes
- Replacement of workflow owner accountability

## Bottom Line

The pilot is not successful because AI was used.

The pilot is successful if one workflow becomes faster, clearer, more reliable, and more measurable without creating unacceptable operational risk.
